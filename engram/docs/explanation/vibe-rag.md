# Vibe RAG, the self-tuning-retrieval program

This is the **program-level explanation** of Vibe RAG: what the program is, the control-loop framing that organises it, and the honest shipped-vs-roadmap state of its phases (0-7). ## 1. What Vibe RAG is

> **Summary:** Vibe RAG is engram's **self-tuning-retrieval program**: the system bootstraps its own evaluation ground-truths *from the structure of the indexed knowledge base*, gold source ids known by construction, never model-guessed (the key inversion), and then self-tunes its retrieval against them. The accuracy signal is **judge-free and structural**, so the loop that consumes it is well-posed rather than at the mercy of a model's opinion.
<!-- load-when: what is vibe rag, self-tuning retrieval, gold from seed, structural ground truth, judge-free, the inversion, program, thesis -->

Plain RAG evaluation has a circularity: you ask a model to retrieve over a knowledge base, and to grade it you ask *another* model whether the answer looks right. The grader's opinion is the yardstick, so the thing being measured (retrieval) is judged by the same class of system doing the retrieving, and any drift in the judge silently moves the bar.

Vibe RAG removes the circularity by reading the ground truth **off the indexed knowledge base itself**. engram's `index` stage already lands a graph: `kb.pages`, `kb.claims`, `kb.edges`, `kb.sections`, whose *shape is a retrieval task*: a single claim is a pinpoint lookup, an edge fan-in is a survey, a multi-hop path is a trace, an out-fanning page is a synthesis. If a generated eval case is *seeded* from one of those structures, the source pages that contribute to it **are** the correct answer, known before any model runs.

That is the **gold-from-seed inversion** ([ADR-0016](../adr/0016-structural-eval-generation.md)): the structural seed fixes the `gold_ids`, the `page_type`, and the difficulty. The drafting model writes only the question, the answer, and verbatim support quotes. And a pure quote check keeps a case only when every support quote is verbatim in the seed's source bodies (the same `wikinote.verify.quotes_in_mirror` predicate the note grammar uses). A kept case is therefore **quote-checked by construction** (its citations cannot be fabricated and its quotes cannot be unsupported) rather than trustworthy only if the model behaved. The trust boundary that plain RAG eval inverts is restored: the eval no longer depends on the model getting the ground truth right.

Two consequences follow that the rest of the program leans on. First, **difficulty is derived, not labelled**: `derive_difficulty(n_sources, n_hops, n_sections)` computes a case's `easy` / `medium` / `hard` band from its seed's shape, so difficulty is a reproducible property of the structure (a trustworthy controlled variable), not an authored guess. Second, **dataset volume scales without new content**: a fixed knowledge base becomes a combinatorial seed space (every claim, every comparison, every fan-out, every path), so many balanced datasets come from one indexed knowledge base.

The name is deliberate. "Vibe coding" lets an agent write code and run it. **Vibe RAG** lets the agent's *retrieval* be tuned against ground truth the knowledge base generates about itself, the knowledge base tunes its own reading.

## 2. The control-loop framing

> **Summary:** Read as a control loop, Vibe RAG is well-posed. **Setpoint** = the generated structural ground-truths. **Controlled variable** = the agent's unified `RetrievalPolicy` (instructions + strategy + tool descriptions). **Error signal** = cost / time / accuracy. **Measurement** = `RetrievalMetrics` (recall@k / precision@k / MRR). **Controller** = the tuning loop. Phase 1 built the setpoint + the measurement. Phase 2 built the controller.
<!-- load-when: control loop, setpoint, controlled variable, error signal, measurement, controller, retrievalpolicy, retrievalmetrics, framing -->

| Control-loop role | In Vibe RAG | Built by |
|---|---|---|
| **Setpoint** (the target) | the generated structural ground-truths, gold ids correct by construction, so `recall@k` against them is deterministic | Phase 1 ([ADR-0016](../adr/0016-structural-eval-generation.md)) |
| **Controlled variable** (the knob) | the agent's unified `RetrievalPolicy`, `instructions` (the agent-under-test system prompt) + `strategy` (a named retrieval surface) + `tool_descriptions` (per-tool MCP overrides), bundled into one frozen artifact | Phase 2 ([ADR-0018](../adr/0018-calibration-loop.md)) |
| **Error signal** | cost (tokens, latency) and accuracy, the gap between the policy's measured behaviour and the setpoint | Phase 1 + 2 |
| **Measurement** (the sensor) | the `RetrievalMetrics` evaluator (recall@k / precision@k / MRR + tool-call count) over the agent's structured `cited_source_ids`, plus the evaluation harness with its experiments (`engram.evals.harness`) and root-cause analysis (`engram.evals.rca`) | Phase 1 |
| **Controller** | the tuning loop: diagnose the error signal, then propose a revised policy, then evaluate it, then accept-iff-better, then converge | Phase 2 |

Phase 1 built the **setpoint and the measurement**: deterministic gold ids and a metric that reads them. What was missing was the **controller** (the half that reads the error signal, proposes a revised policy, evaluates it, and converges on a better one). Phase 2 is that controller. Bundling the three edit surfaces into one `RetrievalPolicy` is what makes the loop tractable: one object means one search space, one objective, one convergence, not three loose levers with three search spaces and nothing single to optimise, persist, and apply.

## 3. The phase roadmap

> **Summary:** Eight phases (0-7), **all shipped**: the vibe schema, structural ground-truth generation, the propose-only tuning loop, true incremental ingestion, the recommendation loop, coverage-based scaling, freshness via mirror-hash invalidation with staleness-aware dataset maintenance, and the closeout's governance ladder: a runtime-scoped auto-apply rung, frozen-split governance, and reflective diagnosis (ADRs 0014 / 0016 / 0018 / 0019 / 0026 / 0027-0029 / 0030-0031 / 0032-0034). The loop's one machine-writable surface is the per-knowledge-base `_meta/active-policy.yaml`, behind four guardrails. Everything else stays propose-only.
<!-- load-when: phases, roadmap, shipped, phase 0 1 2 3 4 5 6 7, propose only, auto-apply, frozen split, freeze, reflective diagnosis, recommendation loop, incremental ingestion, freshness, anchor hash, mirror hash, staleness -->

| Phase | What it is | Status |
|---|---|---|
| **0, vibe schema** | `/knowledge-base:init` co-designs the per-knowledge-base `KnowledgeBaseSchema` (`knowledge-base-schema.json`). engram ships as a Claude Code plugin, with configure-only `studio init` (scaffold `_meta/`, then migrate DB, then load vocab). The spec is what makes the knowledge base structure legible to later phases, the seeders read the knowledge base's relations from it, so generation is domain-general. | **Shipped** ([ADR-0014](../adr/0014-domain-general-vault-spec-and-plugin.md) / D-25) |
| **1, structural ground-truth generation** | Five retrieval **archetypes**: `pinpoint` (one claim), `contrast` (a comparison matrix), `survey` (an edge fan-in), `trace` (a multi-hop path), `synthesis` (a page fanning out). The **gold-from-seed inversion**: a `SeedQueries` draws a `Seed` whose contributing node ids *are* the gold ids, before any model runs. A pure **quote check** keeps a drafted case only when every support quote is verbatim in the seed's source bodies. Difficulty is **derived** from the seed's shape, never authored. | **Shipped** ([ADR-0016](../adr/0016-structural-eval-generation.md), [../reference/evals.md](../reference/evals.md)) |
| **2, the tuning loop (controller)** | diagnose, then propose a revised `RetrievalPolicy`, then **accept-iff-better** on the primary accuracy metric within a cost guardrail, then converge. A stratified **train/val split** is the overfitting guard: candidates are accepted on the train split, the run's winner is the accepted incumbent with the best **validation** accuracy. Delivery is **propose-only**: `studio evals tune` emits a winning-policy artifact + report and never mutates the live system. A separate explicit `studio evals apply-policy` writes the working tree (and never commits) for a human to review. Two brains, one core: an in-code `pydantic-ai` proposer (CLI) and Claude Code over MCP (`--authoring`). | **Shipped** ([ADR-0018](../adr/0018-calibration-loop.md), [eval-loop.md](eval-loop.md)) |
| **3, true incremental ingestion** | Re-architect `index` away from rebuilding the whole knowledge base toward incremental update: a content-hash **manifest** detects changed files, an `identity_hash` split + a persisted **link-reference graph** (incl. danglers) compute a precise dirty-set **closure** so renames / adds / deletes correctly re-resolve unchanged files, load becomes targeted with the AGE graph re-projected only when an edge changed, and lint is persisted per page so the `n_errors` CI gate stays bit-for-bit == a full rebuild. **Incremental by default, `--full` escape hatch**, correctness proven by an `incremental == full` property test. The precise changed-set it emits (narrowed `CitingPagesChanged`) feeds Phase 6 freshness. The least-solved part of the LLM-wiki pattern. | **Shipped** ([ADR-0019](../adr/0019-true-incremental-ingestion.md), [../reference/indexing.md](../reference/indexing.md)) |
| **4, the recommendation loop** | A controller extension that proposes *spec* edits (the S3 surface) rather than only retrieval policy. Deterministic detectors (over-budget gold sections, unreachable gold pairs + mined unlifted links with a **counterfactual edge injection**, over-expansion) feed an LLM proposer whose drafts a pure gate re-validates against the `KnowledgeBaseSchema` and ranks by measured evidence. Two typed op classes (`restructure_sections`, `add_relation`) plus a free-form findings tail. **No pre-apply eval score** (a spec diff is inert until content migrates), so proposals carry falsifiable predictions and per-page migration briefs, `apply-spec` writes only `knowledge-base-schema.json` in the working tree, and `verify-recommendation` re-runs the retained page-level dataset post-migration with manifest-attributed drift. **Human-gated by design**: nothing indexes, migrates, regenerates, or commits. | **Shipped** ([ADR-0026](../adr/0026-structural-advisor.md), [../reference/evals.md](../reference/evals.md)) |
| **5, coverage-based scaling** | Scale generation and tuning to thousands of documents. Coverage is a **stratum** `(archetype × derived difficulty × anchor kind)` measured judge-free from knowledge base structure, and seed selection is a deterministic **salted-hash draw pushed into SQL** (per-stratum quota, `md5(key ‖ salt)` order, staged trace) so the combinatorial seed space is sampled where it matters, never materialized. A read-only `studio evals coverage` verb reports the stratum inventory, gaps, a coverage-debt scalar, and the feasibility manifest. Datasets become **immutable `<name>.v{N}` versions** with a stamp sidecar, seed-derived stable case identity (`{seed_key}#{ordinal}`), and a **coverage-gap top-up** that drafts only under-covered strata and retires displaced cases into a retirement record. Tuning subsamples onto a fixed **decision core** with a paired-bootstrap accept guard (mean gain ≥ `min_gain` **and** the CI lower bound above zero), the validation split scored only on accepts. | **Shipped** ([ADR-0027](../adr/0027-stratified-salted-hash-seed-selection.md) / [0028](../adr/0028-immutable-dataset-versions-and-case-identity.md) / [0029](../adr/0029-decision-core-subsampled-calibration.md), [../reference/evals.md](../reference/evals.md)) |
| **6, freshness via mirror-hash invalidation** | A read-only `studio evals freshness` **check** snapshot-diffs a dataset version's baked anchors + gold ids against the live `kb.*` tables (no `CitingPagesChanged` or manifest dependency, so it cannot miss an indexing run, a non-paper gold page, or a cold-evals window). Verdicts are **graded and era-authoritative**: `gold_gone` > `mirror_stale` (the mirror era's precise signal) > `page_drifted` > `fresh`, `unanchored` for cases with no anchors. And a **mirror-hash seam upgrade** hashes the exact drafting text each case's quotes were verified against, fixing a latent defect (non-pinpoint seeds had carried empty `source_bodies` since Phase 1). Top-up becomes **staleness-aware by default**: stale cases retire (`reason="stale"`) and band-level **deficit cells** redraft the freed slots under historically-unique names. `tune` / `verify-recommendation` record a **warn-never-gate** `dataset_staleness`. Propose-only throughout. | **Shipped** ([ADR-0030](../adr/0030-freshness-via-mirror-hash-invalidation.md) / [0031](../adr/0031-staleness-aware-dataset-maintenance.md), [../reference/evals.md](../reference/evals.md)) |
| **7, loop governance (closeout)** | The eval-loop design's remaining governance rungs, buildable once ADR-0029's honest acceptance and ADR-0030's judge-free staleness landed. **The runtime policy rung**: `tune --apply-runtime` may write exactly one surface, the per-knowledge-base `_meta/active-policy.yaml`, and only when **four guardrails** all pass (a frozen sidecar exists, the freshness check on both the dataset and the frozen split refusing unmeasured staleness, the winner is an accepted non-incumbent, the winner **beats the incumbent on the frozen split**), with every apply snapshotted append-only into `_meta/policy-history/` and reversible via `evals rollback-policy`. The tuned policy's `instructions` join the runtime surface (the `evals run` default and the MCP server banner). **Frozen-split governance**: `evals freeze` carves a stratified salted-hash **frozen sidecar** (`<name>.frozen.v{M}.json` + a `.frozen.current` pointer) that tuning excludes from train/core/tail/validation and scores exactly twice per run (baseline + winner), the never-optimized-against yardstick. A stale frozen split is frozen again by a human only. **Reflective diagnosis**: per-case error-type detectors (`gold_missed` / `gold_buried` / `over_fetch` / `abandoned`) route S1/S2, a gated LLM reflector turns the structural diagnosis into findings that **recommend to the proposer** (a recommendation only, the measurements decide), and each finding's falsifiable predictions are graded against the next round's measured deltas. Plus a report-only structural-integrity premise check per seed-key format. The freshness check is CLI-only. | **Shipped** ([ADR-0032](../adr/0032-runtime-policy-rung.md) / [0033](../adr/0033-frozen-split.md) / [0034](../adr/0034-reflective-diagnosis.md), [../reference/evals.md](../reference/evals.md)) |

The shipped boundary is worth stating plainly: **the loop's one machine-writable surface is the per-knowledge-base `_meta/active-policy.yaml`, and only behind the four ADR-0032 guardrails**: per-invocation consent (`--apply-runtime` is never a default), a frozen yardstick it must beat, a freshness check that refuses what it cannot measure, and an append-only history with an explicit rollback verb. Everything else keeps the propose-only seam: `apply-policy` writes the working tree and stops (shipped code, the `DEFAULT_INSTRUCTIONS` constant, the skill's managed block, is **permanently human-gated**, as are S2b baked knobs, which live in migrations), and Phase 4's schema proposals stay human-gated for the same reason. Auto-applying a one-knowledge-base signal beyond that bounded runtime surface was judged too much autonomy. The ladder's higher rungs are deliberately not built.

## 4. Relation to the eval loop

> **Summary:** [eval-loop.md](eval-loop.md) owns the loop *mechanics*: the 4th loop, phases 0-6 of one eval cycle, the gates and standing rules. This doc owns the *program* that organises the forward roadmap. Vibe RAG's shipped phases (0-7) realise the eval-loop design piece by piece: Phase 1 its Generate phase, Phase 2 its propose-only Diagnose-to-Act controller, Phase 5 its variance-honest subsampling, Phase 6 its dataset-freshness governance, and Phase 7 its remaining governance rungs: the frozen split, a runtime-scoped slice of the auto-apply ladder, and the reflective-diagnosis discipline (recommendation findings + graded predictions). The ladder's higher rungs (shipped-code and S2b baked-knob auto-apply) are permanently human-gated by decision, not remaining roadmap.
<!-- load-when: relation to eval loop, mechanics vs program, fourth loop, eval loop, cross reference, what owns what -->

The two documents are complementary, not overlapping:

- **[eval-loop.md](eval-loop.md)** is the design rationale for *one cycle* of the evaluation loop: engram's "4th loop", the quantitative successor to LLM-wiki's self-audit "lint". It owns the phase-by-phase mechanics (Pre-flight to Generate to Run to Trace to Diagnose to Act to Verify), the Iron Law ("if a change can't beat the frozen held-out set by a measured margin, it didn't happen"), the three surfaces (S1 instructions / S2 config / S3 schema), and the standing guards.
- **This doc** is the *program* that the cycle serves. It names why the loop is well-posed (the gold-from-seed inversion makes the setpoint deterministic), frames the whole thing as a control loop, and tracks the per-phase shipped-vs-roadmap state.

Concretely: eval-loop.md's **Generate** phase (section 5) is realised by Vibe RAG **Phase 1**. Its **Diagnose-to-Act** controller half (sections 8-9) is realised by Vibe RAG **Phase 2** (propose-only) and **Phase 7** (the bounded runtime rung). Its Pre-flight frozen-split discipline (section 4) is mechanized by Phase 7's `evals freeze`. And its reflective-diagnosis shape (section 8) is realised as detectors + a gated reflector offering recommendations only, with next-round prediction grading. What the eval-loop design describes *above* that (auto-applying shipped code or S2b baked knobs) is not unbuilt roadmap but a standing decision: those surfaces stay human-gated ([ADR-0032](../adr/0032-runtime-policy-rung.md)).
