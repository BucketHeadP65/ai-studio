## Overview

The thread starts from session cold-start — every new session the coding agent knows nothing — and ends at a disclosure protocol.
[[mu.lifecycle-as-consolidation]] is the frame: four knowledge layers, the pain in L2 (working knowledge), the lifecycle read as
episodic-to-semantic consolidation, and the factoring move that produced this corpus. [[mu.enforcement-tiers]] says how much of a disclosure
protocol is actually enforceable, per runtime. [[mu.disclosure-envelope]] is the dated design decision that follows from it.

[[mu.evidence-kinds-doctrine]] is grouped here as well as under [[hub.judges-thread]]: this thread's provenance-carrying units and the
sibling thread's verdicts look like the same typed, signed, provenance-first artifact — "probably one doctrine, two surfaces", still an open
fork.

Decisions the thread took, recorded in [[bs.memory-engineering-lifecycle]] rather than in a unit. From §6's open-fork list: **dogfood before
product** (fork 1, 2026-08-08) — point engram at this repo's own working knowledge first, extract the general capability afterwards from
what survives real use; **unit of memory = the note layer, piloted on these two live brainstorm threads** (fork 2, 2026-08-08; alternatives
considered: compile the existing docs as-is — quick retrieval, no shared-memory factoring; shared-doctrine notes only — deferred, subsumed
by the pilot); **vocabulary** (fork 8, 2026-08-08) — the atomic unit is a *memory unit* and the store is a *corpus*, on literature
convergence rather than branding. Recorded separately at the end of §9, not in §6: **fork 10, summary provenance** (2026-08-08) — disclosure
summaries are compiled and governed, regenerated on source change so staleness is mechanical, quarantined and eval-gated as autonomous
writes (alternatives: authored at promotion — trustworthy voice but rots; a hybrid authored-abstract plus compiled ladder — deferred).

Still open in the doc: where units live and what is gitignored, the write policy (live vs batched), the retrieval interface (MCP at session
start vs a hook vs an explicit skill), contradiction and supersession policy for reversed decisions, and who owns the disclosure logic. The
doc also carries material no unit compresses: the three access rungs (deterministic walk → reasoning-guided tree search → associative
search), the one-substrate spine with per-node summaries and typed links, the three-phase schema contract (structure, disclosure, emission),
the presentation forms and their `strict`/`auto(N)`/`search_only` modes with the maintenance hooks the degradation needs, and the reading
notes on HiGram (the four-state status vocabulary, dependency-aware invalidation, the three conflict kinds) and PageIndex.
